# Project K：設計精神與能力規格

版本：v0.2，供 H.C. Chen 審閱。日期：2026-10-04。

## 1. 願景

Project K 是一個可嵌入宿主環境、能由極少起點逐步擴充的 Forth 核心。

它讓使用者以 Forth 的方式組織工作，同時直接借用宿主語言與環境已具備的能力。使用者可以從少量定義機制出發，建立自己的操作、語法與工具，形成適合當下任務的系統。

**核心提供生長的能力；系統的豐富性由後續定義逐步長出來。**

本規格以這個精神指引新實作。原始 Python 程式是理解設計的參考；本規格保留其核心能力，並授權實作者以目標語言自然、清楚的方式重新設計。

## 2. 設計原則

### 精簡且足以自我擴充

初始核心應小到容易理解，同時具備建立後續功能的能力。凡是能合理地透過既有機制建立的功能，優先交由擴充層實現。

「精簡」以概念和機制的少量為準，不追求特定行數，也不要求每種宿主語言採用相同數量的內部函式。

### 與宿主合作

核心使用宿主的運算、資料與外部資源能力。Forth 操作能呼叫宿主能力，宿主也能進入 Forth 執行，兩者能交換資料並共同完成工作。

### 以組合建立複雜度

簡單操作可以連接成序列，序列可以成為新的操作，再參與更大的組合。新建立的能力應能像原有能力一樣被使用。

### 讓使用者擴充語言本身

擴充不只增加運算功能，也可以增加輸入的解讀方式、定義方式及執行控制。核心提供足夠的介入能力，讓高階系統能決定自己的語言形貌。

### 保留持續工作的脈絡

使用者可以逐次輸入、逐步定義與反覆執行。已建立的能力與工作資料持續可用，除非使用者或宿主明確要求結束或清除。

## 3. 從最小起點建立操作

核心應提供最小的宿主能力定義機制：開始一個定義、接收其內容，並完成為可使用的具名操作。

原有的 `code` 與 `end-code` 展示這個起點。新實作可依宿主特性選擇適合的表達方式，只要仍能從極少的初始機制建立後續操作。

在 Forth 語境中，這些可被命名、查找、執行與組合的操作稱為 word。這個概念只要求可識別的行為，不限定它在程式裡必須是物件、類別、函式或某種紀錄。

定義內容可以由宿主程式碼或等效的宿主能力形成。實作者自行選擇動態編譯、預先編譯、函式綁定等方式，使使用者仍能在宿主能力之上持續建立 Forth 操作。

完成的定義應可供後續使用；建立失敗時，系統應清楚呈現失敗，避免將未完成的定義當作可用操作。

## 4. 核心應具備的能力

### 4.1 資料傳遞

以後進先出的資料堆疊作為 Forth 操作之間的主要資料傳遞方式。操作能取用、產生、查看及調整工作資料。

資料可以包含宿主支援的數值、文字與其他值或資源的參照，使 Forth 能處理實際的宿主工作。具體型別與表示方式由實作者選擇。

執行控制的資訊應有可保存與恢復的方式，與工作資料的用途保持清楚。是否以另一個堆疊實現，由實作者決定。

### 4.2 名稱與定義

系統能保存已建立的操作，依名稱找到它們，也能持有特定定義的參照，以供執行與組合。

系統允許定義逐步演進。當名稱被重新定義時，後續查找與既有組合的使用方式應清楚且一致。具體查找結構、命名空間與重新定義政策，由實作者依最小核心原則設計並說明。

### 4.3 依語境取得輸入

系統能從目前的輸入中，取得當下工作所需要的一段內容，並保留繼續處理剩餘輸入的能力。

所需內容可能是名稱、數值的文字、一行說明、具有空白的文字，或跨行的宿主程式碼。讀取範圍與結束條件由目前的語境或操作決定。

一般處理與自訂操作應能協調輸入的消費：某個操作取走它需要的內容之後，後續處理從正確位置繼續。擴充層可以藉此建立新的語法和內容區塊。

此能力不預設所有輸入都是 token。實作者自行決定介面、名稱、分隔方式與解析工具。

### 4.4 執行與建立可重用行為

系統能直接執行已知操作，並能將一段操作與資料的使用方式組合、保存，供之後重複執行。

輸入處理應能依當下狀態，選擇立即執行或建立後續可執行的行為。定義過程中的某些操作可以當場介入，改變組合方式、讀取內容或完成定義。

常見數值應能成為工作資料，也能納入可重用行為。數值語法與型別由目標實作選定，並保持輸入與執行結果的一致性。

核心應讓高階系統能建立這些使用方式；不要求初始核心就內建所有常見 Forth words 或完整語法。

### 4.5 組合、呼叫與返回

操作能呼叫其他操作，完成後正確回到呼叫端。系統能執行由多個操作組成的行為，並容許擴充層建立所需的執行控制。

控制流程應清楚區分繼續執行、完成返回、暫時讓出控制與中止工作。如何保存執行位置、表示指令或實現執行迴圈，由實作者決定。

### 4.6 暫停、繼續與巢狀工作

工作可暫時讓出控制給宿主，保留尚未完成的脈絡，並在適當時候繼續。暫停與完成具有不同意義。

執行中的工作可以進入另一段 Forth 工作；內層結束後，外層能在正確位置繼續。資料的共享與必要的執行脈絡應有一致的處理方式。

這項能力不要求並行、背景排程或跨程序保存；實作者可用最簡單的方式達成。

### 4.7 失敗處理與重新工作

遇到無法理解的輸入、無法完成的定義或執行失敗時，系統應提供足以理解問題的訊息，並讓使用者或宿主能回到可繼續工作的狀態。

中止當次工作、暫停工作與清除整個系統，應有清楚的不同意義。失敗不應默默成為成功，也不應讓輸入處理停滯而持續重複同一失敗。

顯示方式、例外機制與復原介面，由宿主整合決定。

## 5. 宿主與擴充層的分工

| 層次 | 主要責任 |
| --- | --- |
| 核心 | 提供資料傳遞、定義、輸入取得、組合執行及控制脈絡等基本能力 |
| 宿主 | 提供目標語言的運算與資源，並使雙向呼叫、資料交換與診斷可用 |
| 擴充層 | 以核心機制建立運算、控制語法、命名管理、互動工具與應用功能 |

同一個核心應能服務不同應用。介面與應用功能應可由宿主或擴充層選擇，讓核心維持精簡。

## 6. 實作者的自由與責任

實作者可以自行決定函式名稱、介面形狀、內部資料結構、記憶體配置、指令表示、解析工具與錯誤機制。既有 Python 實作的特殊值、欄位與邊界行為不構成新實作必須沿用的要求。

選擇應服務於以下目標：

- 核心少而清楚，容易閱讀、嵌入與擴充。
- 使用者能從小起點逐步建立實際可用的系統。
- 同一能力在不同情境中有一致、可理解的行為。
- 宿主與 Forth 能自然交換能力、資料與控制。

具體實作完成時，應簡要說明所選的使用語法、宿主介面及必要的行為政策，使使用者能操作及驗證。這些說明屬於該實作的設計成果，無須先逐一變成本規格的限制。

原始碼中的筆誤、型別偶然性與歷史處理方式，可依上述原則自然消除。

## 7. 以使用情境驗收

驗收著重能力與使用結果。每種語言可採用自己的寫法完成相同情境。

| 情境 | 應看到的結果 |
| --- | --- |
| 從最小核心開始 | 能借用宿主能力建立第一個自訂操作，並以名稱使用它 |
| 逐步生長 | 能用已建立的操作組合出新操作，再繼續組合 |
| 資料合作 | 操作透過堆疊傳遞資料，並能使用宿主的資料或資源 |
| 依語境讀取 | 能分別取得名稱、一行文字與多行內容，之後仍正確處理剩餘輸入 |
| 建立後重用 | 一段行為能保存並重複執行，維持預期順序與資料效果 |
| 定義時介入 | 擴充操作能在建立行為時讀取內容或改變建立過程 |
| 雙向呼叫 | 宿主可進入 Forth，Forth 可使用宿主，完成後回到正確呼叫端 |
| 暫停再繼續 | 讓出控制後，能延續尚未完成的工作，效果相當於連續執行 |
| 巢狀工作 | 內層工作結束後，外層正確繼續，資料效果可理解 |
| 從失敗恢復 | 錯誤可被辨識；下一次有效工作能正常進行，先前成功建立的能力仍可使用 |
| 形成自己的系統 | 能以擴充層建立一個小型可用的 Forth 環境，展示核心的生長能力 |

## 8. 交給 AI 實作的任務

> 請以指定的宿主語言實作 Project K，依本規格保留其精簡、可嵌入、可自行擴充的精神與能力。請自主選擇適合目標語言的設計、命名與資料結構，使系統能從最小的宿主能力定義機制開始，逐步建立並組合 Forth 操作。請提供簡要的使用說明與可執行示範，依第 7 節驗證結果。若某項能力受到宿主限制，請提出可達成該能力的設計方式，並清楚說明使用上的影響。
